# 욱채 서버 — 무엇인가

욱채를 처음 보는 AI가 이 PC의 서버를 바르게 다루도록 그림을 그립니다. 원본은 [../기획서_v0.5.md](../기획서_v0.5.md) 1·2장, [../ARCHITECTURE.md](../ARCHITECTURE.md) 4장·20장, [../SERVER_INSTALL.md](../SERVER_INSTALL.md), [../SERVER_DESIGN.md](../SERVER_DESIGN.md)입니다. 둘이 다르면 SERVER_DESIGN이 맞습니다.

## 욱채

- 대표가 메인 에이전트에게 명령을 내리면, 메인 에이전트가 프로젝트별 AI 팀(Claude·Codex 세션)을 꾸리고 지휘해 결과를 정리·보고하는 프로그램입니다. 프로그램이 안에서 Claude Code CLI와 Codex CLI를 실행합니다.
- 팀은 개발 회사처럼 일합니다. 프로듀서가 지시를 작업으로 쪼개 팀원에게 배정하고, 팀원은 각자의 작업 공간(git 브랜치와 작업 폴더)에서 일한 뒤 검수를 거쳐 결과를 합치고, 결과는 보고서로 대표에게 올라갑니다.
- 두 모드가 한 코어를 씁니다: Windows의 데스크톱 앱(Electron)과 화면 없는 서버(Node). **이 묶음은 서버 모드만** 담았습니다. 대표는 서버에 휴대폰이나 다른 PC의 브라우저로 Tailscale을 거쳐 들어옵니다.
- 실행 권한 승인은 건너뜁니다(바이패스). 서버가 띄우는 CLI는 이 사용자가 닿는 모든 것에 승인 없이 닿습니다. 그래서 서버는 root로 돌지 않고, 이 계정에는 믿는 프로그램만 둡니다.

## 역할

| 역할 | 누구 | 하는 일 |
|---|---|---|
| 대표 | 구글로 로그인한 주인 한 명(server.json의 `owner.email`) | 명령을 내리고 보고서를 승인·수정 요청합니다. 긴급 정지를 걸고 **풀 수 있는 것은 대표뿐**입니다 |
| 메인 에이전트 | 메인 자리에 앉은 보유자 하나 | 대표의 명령을 받아 팀 구성·지시·보고 정리를 맡습니다 |
| 메인 자리의 보유자 | `launched:claude`(서버가 띄우는 Claude CLI), `launched:codex`(Codex CLI), `external:<ID>`(외부 에이전트) | 한 번에 하나만 앉습니다. 자리를 바꾸는 것은 메인 자신(`hand_off_seat`)과 운영자(`wook-server seat assign`)뿐이고, 서버는 응답하지 않는 메인을 스스로 바꾸지 않습니다. 대표 화면에는 자리를 바꾸는 버튼이 없습니다 |
| 프로듀서, 팀원 | 프로그램 안의 개체(이름·역할·AI 설정·이력) | 작업이 있을 때만 서버가 CLI 프로세스(턴)를 띄워 일하게 합니다 |
| 운영자 | 서버 PC에서 `wook-server` 명령을 치는 사람(또는 당신) | 설치, 설정, 켜고 끄기, 비밀 값, 메인 자리 배정, 외부 에이전트 등록. 관리 채널로만 서버를 다룹니다 |
| 외부 에이전트 | 운영자가 등록한, 이 PC에서 도는 다른 프로그램(그록봇 같은 것 — 나중의 당신일 수 있음) | 운영자가 배정하면 메인 자리에 앉아 서버가 띄운 CLI와 같은 일을 같은 규칙으로 합니다 |

## 프로세스

- **서버**: `node ~/wookagent/out/server/index.mjs serve …` 하나. systemd 사용자 유닛 `wook-server-<8자>.service`가 이 사용자로 띄웁니다(linger면 부팅 때). 한 데이터 폴더는 한 프로세스만 씁니다 — 실행 잠금(`server.lock`)과 데이터의 주인 기록이 두 번째를 막습니다.
- **CLI 턴**: 서버가 이 사용자로 Claude Code·Codex CLI를 띄웁니다. 로그인은 이 사용자의 것(`~/.claude`, `~/.codex`)을 씁니다. 실행마다 프로세스 그룹(`setsid`)으로 띄우고, 정지할 때 그룹과 그룹을 떠난 후손을 `/proc`으로 찾아 끝냅니다(한계는 [TROUBLESHOOT.md](TROUBLESHOOT.md)의 '정지 뒤에 남은 프로세스').
- **절전 방지**: 작업 중에는 `systemd-inhibit`을 쥔 자식 프로세스로 절전을 막으려 합니다(polkit이 거부하면 `unavailable`).
- **화면 도우미**(화면 조작을 켰을 때): 서버의 Node가 띄우는 `<데이터 폴더>/bin/wook-x11-helper.mjs`와 곁 도우미 `wook-x11-sidecar.py`(python3). 서버가 복사해 해시로 고정하고 띄울 때마다 확인합니다. X 도구(xdotool·maim 등)를 `/usr/local/bin`·`/usr/bin`·`/bin`에서만 찾습니다.
- **화면 유닛**(선택): `wook-xvfb.service`(Xvfb `:99`)와 `wook-openbox.service`(창 관리자). 서버와 따로 도는 사용자 유닛입니다.

## 폴더와 파일

| 자리 | 무엇 | 다루는 법 |
|---|---|---|
| `~/wookagent` | **앱 폴더** — 이 묶음 | 새 판으로 통째로 바꿉니다. 안의 파일은 고치지 않습니다 |
| `~/wook-data` | **데이터 폴더** — 0700, 경로 96바이트 이하. `--data-dir`을 주지 않으면 기본 자리는 `~/.config/wookagent`(`XDG_CONFIG_HOME`이 있으면 그 아래) | 바꾸거나 지우지 않습니다. 손대는 것은 `server.json`(문서의 방법으로)뿐 |
| `~/wook-workspace/main` | 메인 에이전트의 작업 폴더(server.json `workspaceRoot` 아래 `main`, git 저장소). 화면 캡처는 그 안 `screens/`(24시간·최근 500장) | 지우지 않습니다 |
| `~/.config/systemd/user/` | 유닛 파일(`wook-server-<8자>.service`, 화면 유닛 둘) | `install-task`·`uninstall-task`로만 |
| `~/.wook/` | 외부 에이전트의 키(`agent.json`)와 임대·턴 토큰(`state.json`) — 0700·0600 | 읽어 출력하지 않습니다 |
| `~/.wook-xvfb.auth` | Xvfb 화면의 쿠키 | 쿠키 값을 출력하지 않습니다 |
| `~/.local/opt/node-v24…` | Node(L1의 방법일 때). `~/.profile`에 PATH 한 줄 | 옮기면 `install-task`를 다시 |
| `~/.claude`, `~/.codex` | CLI의 로그인과 CLI가 스스로 남기는 기록(캡처 사본이 들 수 있음 — 앱이 지우지 못함) | 손대지 않습니다 |

데이터 폴더 안(원본에 적힌 것):

- `wook.db`(SQLite — 작업·상태·정지·요청 기록), `server.json`(운영자 설정 — 비밀 값 없음), `server.lock`(실행 잠금), `admin.token`(관리 토큰 — 시작마다 새로 씀), `admin.endpoint`(관리 채널 자리), `admin.sock`(관리 채널 소켓), `agent-endpoint.json`(에이전트 API 주소와 확인값 `proof` — 키는 없음, 시작마다 바뀜), `setup-code.txt`(대표 이메일이 없을 때만), `secrets/`(비밀 값 파일 — 0700·0600, 암호화하지 않음).
- `logs/server.log`·`logs/backend.log`(기록 — 5MB마다 회전, 비밀 값 가림), `bin/`(화면 도우미 사본과 `.sha256`), `uploads/`(대표가 올린 파일 — 24시간), `backups/<YYYY-MM-DD>/`(자동 백업 7개)와 `backup-state.json`.
- 팀의 자료: `worktrees/`(작업마다의 작업 폴더), `review/`(검수용 사본), `reports/`(보고서), `events/`(가린 CLI 이벤트), `artifacts/`, `memory/`, `attachments/`, `tmp/turns/`.

## 비밀 값

- 서버가 쥐는 비밀 값은 구글 로그인 보안 비밀(`google-client-secret`)과 AI의 API 키(`claude-api-key`·`codex-api-key` — API 키 방식일 때만)입니다. 운영자가 `secret set`으로 표준 입력에 넣습니다.
- Linux에서는 OS 키링이 아니라 데이터 폴더의 `secrets/`에 이름마다 파일 하나(`<이름의 SHA-256>.json`)로 둡니다. 막는 것은 이 PC의 **다른 사용자**뿐입니다. 같은 사용자의 프로세스(서버가 띄우는 CLI, 같은 계정의 외부 에이전트, 당신)는 읽을 수 있습니다 — 서버는 그 값을 기록·도구 결과·대화에서 가립니다. 권한이 넓어지거나 주인이 다르거나 링크면 서버가 시작하지 않습니다.
- 그 밖의 비밀 같은 값: 설정 코드(8자, 1시간, 한 번), 외부 에이전트 키 `wsk_…`(등록할 때 한 번만 보임, 서버는 해시만 둠), 턴 토큰 `wtt_…`(턴마다, 턴이 끝나면 죽음), 관리 토큰, 기기 세션 토큰, 화면 쿠키.
- 믿음의 범위(SERVER_DESIGN 9.2): 서버 PC의 운영자와 그 PC에서 도는 에이전트를 믿는다는 전제입니다. 같은 OS 계정의 프로그램은 데이터 폴더를 읽을 수 있습니다.

## 네트워크와 대표의 접속

- 서버는 이 PC의 **루프백**(같은 포트의 127.0.0.1과 ::1, 기본 포트 7317)에서만 듣습니다. 웹 화면(`out/web`)과 대표용 API가 이 포트에 있습니다. `--bind`에 루프백 밖 주소를 주면 시작하지 않습니다.
- 다른 기기는 서버 앞에 둔 `tailscale serve`로 들어옵니다: `https://<서버 PC 이름>.<tailnet>.ts.net` → `http://127.0.0.1:7317`. 이 주소가 server.json의 **공개 주소**(`network.publicOrigin`)이고, 서버는 그 주소의 Host·Origin만 더 받습니다. `tailscale funnel`(인터넷 전체)은 쓰지 않습니다.
- **받는 Tailscale 사용자**(`owner.tailscaleLogins`): `tailscale serve`가 붙이는 `Tailscale-User-Login` 머리를 보고 목록 밖의 요청을 403으로 막습니다. 인증이 아니라 겹 방어입니다.
- **대표 로그인**: 구글 기기 코드 로그인('TV 및 입력 제한 기기' 클라이언트). 대표가 휴대폰에서 공개 주소를 열면 코드가 나오고, google.com/device에 넣어 승인합니다. 브라우저 로그인은 공개 주소에서만 받습니다. 로그인한 브라우저에는 기기 세션(쓰지 않고 14일, 최대 90일)이 생기고, 새 기기가 로그인하면 다른 기기에 알림이 갑니다.
- **관리 채널**: 운영자 명령은 데이터 폴더의 `admin.sock`(이 사용자만)으로 붙고, `admin.token`으로 서버와 서로 증명한 뒤에만 실행됩니다. 다른 기기에서는 닿지 않습니다.
- **에이전트 API와 앱 도구**: 외부 에이전트의 길(`/agent/v1/*`)과 CLI가 쓰는 앱 도구 서버(MCP)는 대표용 포트와 다른 루프백 리스너에 있고, 포트는 시작마다 바뀝니다(`agent-endpoint.json`). `tailscale serve`로는 닿지 않습니다.

## 화면 조작 (Linux)

- 메인 에이전트가 서버 PC의 화면을 찍고(`screen_capture`) 마우스·키보드를 움직입니다(`gui_input`). 대표는 웹 화면에서 상태와 기록을 보기만 하고, 멈추려면 긴급 정지를 씁니다.
- 지원하고 시험한 모양은 이 사용자의 **Xvfb 가상 화면과 openbox**입니다(설치 INSTALL.md L9). 실제 X 데스크톱은 최선 노력, Wayland는 쓸 수 없습니다.
- 서버는 X 도구를 띄우기 전에 python3로 그 화면의 주인을 확인하고, 아니면 쓰지 않습니다. 암호 칸과 어떤 칸인지 모르는 칸에는 글자를 치지 않습니다(AT-SPI — 세션 버스가 있어야 가를 수 있습니다). 사람이 그 화면을 쓰면 30초 멈춥니다. 가운데 단추 클릭과 일부 키 조합은 받지 않습니다. 자세한 한계는 [TROUBLESHOOT.md](TROUBLESHOOT.md)의 '화면 조작'.
- 서버는 `DISPLAY`·`XAUTHORITY`를 CLI 턴과 `host_exec`에 넘기지 않습니다. 그 화면에 띄울 프로그램은 운영자가 띄워 둡니다.

## 외부 에이전트로 메인 자리에 앉을 때

설치를 마친 당신이 나중에 외부 에이전트로 메인 자리에 앉을 수 있습니다. 안내서는 [../AGENT_GUIDE.md](../AGENT_GUIDE.md)이고, 그대로 따릅니다. 그 안내서는 Windows 기준으로 쓰였으므로 이 PC에서는 아래가 다릅니다.

- `wook`은 `node ~/wookagent/out/server/wook.mjs`입니다(앱 폴더에서는 `node out/server/wook.mjs`). 도움말: `node out/server/wook.mjs --help`.
- 데이터 폴더의 기본 위치는 `~/.config/wookagent`입니다. 이 설치는 `~/wook-data`를 쓰므로 `wook … --data-dir "$HOME/wook-data"`나 환경 변수 `WOOK_DATA_DIR="$HOME/wook-data"`를 줍니다. `wook`은 그 폴더의 `agent-endpoint.json`으로 서버를 찾고 확인합니다.
- 키는 환경 변수 `WOOK_AGENT_KEY`나 `~/.wook/agent.json`입니다. INSTALL.md L10의 블록이 키를 화면에 내지 않고 이 파일(0600)에 씁니다. 그룹·다른 사용자 권한이 있으면 `wook`이 키를 쓰지 않고 2로 끝나며, 그 글에 따옴표로 감싼 `chmod 600 "<파일>"`이 나옵니다(AGENT_GUIDE 2절이 말하는 `icacls`는 Windows의 것입니다).
- 상태 파일은 `~/.wook/state.json`(`HOME` 아래)입니다. 한 계정에서 에이전트를 둘 돌리려면 `HOME`을 따로 줍니다.
- 셸은 bash입니다. AGENT_GUIDE의 Windows PowerShell 5.1 이야기(`--json` 대신 `--json-file`, `>`가 UTF-16으로 씀, `curl.exe`)는 이 PC와 상관없습니다. `--json '<JSON>'`을 작은따옴표로 넘기면 됩니다. 답 파일이 UTF-8이어야 하는 것은 같습니다.
- 화면(AGENT_GUIDE 7절): `wook screen capture --out <파일.png>`와 `gui_input`은 같습니다. 화면 조작은 L9를 했을 때만 됩니다. Xvfb에는 멈춤 단축키(Ctrl+Alt+Shift+F12) 규칙이 없고 대표의 멈춤은 긴급 정지입니다. 글자 입력은 위 '화면 조작'의 한계를 따릅니다.
- 남은 CLI 프로세스 확인(SERVER_INSTALL 6절의 '작업 관리자'): 이 PC에서는 `ps -eo pid,pgid,cmd`입니다.
- 서버 확인(hello)은 `wook`이 연결마다 스스로 합니다 — 키를 보내기 전에 듣는 쪽이 `agent-endpoint.json`을 쓴 서버인지 봅니다. 당신이 따로 할 일은 없습니다. 환경 변수 `WOOK_AGENT_URL`은 쓰지 않습니다(그 길은 `WOOK_AGENT_PROOF`를 함께 주지 않으면 듣는 쪽을 확인하지 않고, 서버가 다시 시작할 때마다 두 값을 바꿔야 합니다).
- 임대(60초)를 늘리는 것은 임대를 싣는 요청뿐입니다 — heartbeat, 일 받기(`work next`), 진행(`work progress`), 마치기(`work done`). 도구 호출과 보기는 늘리지 않습니다. `wook tool`·`wook screen capture`·`wook work next --wait`는 기다리는 동안 heartbeat를 스스로 보내지만, **명령과 명령 사이(당신이 생각하는 동안 포함)는 당신이 15초마다 `wook seat heartbeat`를 보내야 합니다.** 60초를 넘기면 임대가 끝나고 `wook seat claim`부터 다시 해야 합니다. 오래 걸리는 턴이면 그 턴 동안만 도는 반복을 곁에 두고 `work done` 뒤에 멈춥니다 — 끝없이 도는 반복은 당신이 멈춰도 자리가 살아 있는 것처럼 보이게 합니다.
- 상태를 바꾸는 도구에는 까닭(`reason`)을 꼭 적습니다. `request_id`는 다시 보내기를 위한 것입니다 — 같은 호출을 다시 보낼 때는 같은 값을, 새 호출에는 새 값을 씁니다(턴마다 받는 `instructions`에 있습니다).
- 팀원 이름은 사람 이름입니다(한글 2~4자, 예: 서진). 대표는 사무실 화면에서 머리 위의 이름으로 팀원을 봅니다. `add_member`의 `name`은 비워 두면 서버가 지어 줍니다. '코덱스 개발1'처럼 AI 종류·역할·번호로 만든 이름을 주면 서버가 받지 않고 사람 이름을 지으며, 결과의 `name`이 실제 이름이고 `nameNote`에 까닭이 있습니다. `update_member`로 그런 이름으로 바꾸면 거부됩니다.
- 팀원의 AI는 당신이 정합니다 — AI 종류, **모델**, 노력치 셋 다입니다. `list_ai_options`의 `models`에서 맡길 일에 맞는 모델을 id로 고릅니다(모델마다 용도가 적혀 있습니다). 설계·검수·복잡한 디버깅은 모델과 노력치를 높게, 문서·단순 반복은 낮게. 모델을 비운 결정은 서버가 받지 않고 고를 수 있는 모델 목록을 알려 줍니다: `set_member_ai`에는 `model`을 주고(이미 모델이 있는 팀원은 생략하면 그대로), `add_member`에 `ai_kind`·`effort`를 줄 때는 `model`도 함께 줍니다. AI 인자 없이 추가한 팀원은 이어서 오는 'AI 결정' 일에서 `set_member_ai`로 정합니다.
- 이 PC의 CPU 사용률이 95%를 넘지 않게 일합니다. 서버는 CPU가 95% 이상이면 새 팀 턴을 띄우지 않고 `host_exec`를 내려갈 때까지 미룹니다(거부가 아니라 미룸 — `host_exec`는 그대로 기다리면 내려간 뒤에 실행되고 결과의 `cpu_delayed_ms`에 미룬 시간이 옵니다). 지금 사용률은 턴마다 받는 현황 요약의 '서버 PC CPU' 줄과 `get_overview`의 `cpu`에 있습니다. **당신의 셸에서 직접 치는 명령은 서버를 거치지 않아 이 미룸이 닿지 않습니다** — 빌드·전체 시험·압축·설치 같은 무거운 명령은 치기 전에 사용률을 보고(`get_overview`), 95%에 가까우면 내려갈 때까지 기다렸다가, 한 번에 하나씩 병렬 수를 줄여(코어 수의 절반 이하) 돌립니다. 팀에도 무거운 작업을 한꺼번에 여러 개 맡기지 않습니다.
- 긴급 정지는 당신의 임대와 턴 토큰을 폐기하지만 당신의 프로세스는 끄지 않습니다. 정지 중에는 일을 받지 못하고, 대표가 풀면 `wook seat claim`부터 다시 합니다. 풀려도 보류된 작업은 저절로 이어지지 않습니다 — 그 목록이 '정지 해제' 일로 오고, 항목마다 확인해 이어 가도 되는 것만 `resume_task`로 재개한 뒤 재개하지 않은 것과 그 까닭을 대표에게 알립니다. 서버가 다시 시작해도 임대가 사라지므로 `claim`부터 다시 합니다.
- 같은 계정이라 당신은 데이터 폴더와 `secrets/`를 읽을 수 있지만 읽지 않습니다. 키·턴 토큰·`proof`는 진행 글·답·도구 인자에 쓰지 않습니다.
- 서버가 띄우는 메인 에이전트는 `host_exec`로 운영자 명령을 돌리지 못합니다(실수 막기). 외부 에이전트의 셸에는 그 막음이 없으므로, 메인 자리의 턴 안에서는 운영자 명령(`scripts/wook-server …`)을 쓰지 않습니다. 메인으로서 자리를 넘길 때는 `hand_off_seat` 도구를 쓰고, 운영자의 일이 필요하면 사람에게 알립니다. 메인 자리에서 일하는 규칙은 턴마다 받는 `instructions`가 정합니다.

## 용어

| 낱말 | 뜻 |
|---|---|
| 대표 | 구글로 로그인한 욱채의 주인. 최상위 사용자 |
| 운영자 | 서버 PC에서 `wook-server` 명령으로 서버를 설치·운영하는 쪽 |
| 메인 에이전트, 메인 자리 | 대표 직속 총괄 에이전트와 그 자리. 보유자 하나 |
| 보유자 | 메인 자리에 앉은 쪽: `launched:claude`·`launched:codex`·`external:<ID>` |
| 세대 | 메인 자리가 바뀔 때마다 오르는 번호 |
| 임대 | 외부 에이전트가 자리를 쥔 기간(60초 — heartbeat로 늘림) |
| 인계 꾸러미, 인계 메모 | 자리를 넘길 때 새 메인에게 가는 정리 |
| 응답 없음 | 메인이 일을 하지 못하는 상태. 서버는 알리기만 하고 바꾸지 않습니다 |
| 프로듀서, 팀원 | 프로젝트의 팀 책임자와 팀의 구성원(프로그램 안의 개체) |
| 지시, 작업, 단계 | 대표의 명령 한 건, 그것을 쪼개 팀원에게 준 일, 작업 안의 체크리스트 항목 |
| 검수, 병합 | 작업 결과를 다른 쪽이 확인함, 통과한 변경을 기준 브랜치(main)에 합침 |
| 턴, 세션 | CLI를 한 번 실행해 끝날 때까지, 팀원·업무별 대화 문맥 |
| 앱 도구 | 에이전트가 프로그램 기능을 쓰는 통로(MCP). `host_exec`는 서버 PC에서 명령을 돌리는 앱 도구 |
| 앱 폴더, 저장소 폴더 | 이 묶음(`~/wookagent`). 원본 문서의 '저장소 폴더'가 이 폴더입니다 |
| 데이터 폴더 | 서버의 DB·기록·설정·비밀 값이 든 폴더(`~/wook-data`) |
| 작업 폴더 | 메인 에이전트가 일하는 폴더(`~/wook-workspace/main`). 원본에서 '작업 공간'은 작업마다의 브랜치와 작업 폴더 |
| 설정용 서버 | 설치 도중 손으로 띄운 서버(L4~L8) |
| 유닛, linger | systemd 사용자 유닛, 그 사용자가 로그인하지 않아도 사용자 유닛을 띄우는 설정 |
| 관리 채널, 관리 토큰 | 운영자 명령의 길(`admin.sock`)과 그 증명 |
| 설정 코드 | 대표 이메일이 정해지지 않았을 때 서버가 내는 일회용 코드 |
| 기기 세션 | 대표가 로그인한 브라우저의 세션 |
| 공개 주소, 받는 Tailscale 사용자 | `tailscale serve`가 만든 https 주소, 받을 Tailscale 로그인 목록 |
| 비밀 값 | 구글 보안 비밀과 AI의 API 키. `secret set`으로만 넣음 |
| 긴급 정지, 정상 종료 | `stop`(새 실행을 막고 도는 실행을 멈춤 — 대표만 풂), `shutdown`(서버를 끔) |
| 배포 점검 | `check` — 이 PC를 17개 항목으로 봄 |
| 절전 방지 | 작업 중 PC가 잠들지 않게 막기 |
| 화면 조작, 화면 도우미, 곁 도우미 | 메인 에이전트의 화면 찍기·입력, 그것을 하는 서버의 스크립트, 멈춤 단축키·조작 중 표시·암호 칸 판정을 맡는 python3 스크립트 |
| 무장(ARM), 놓기 | 화면 도우미가 입력을 보낼 준비를 한 상태, 그것을 풀고 누른 키를 떼는 것 |
| 실행 잠금, 데이터의 주인 | 한 데이터 폴더를 한 프로세스만 쓰게 하는 장치 둘 |

| 시험용 세션 | `--allow-test-session`으로만 켜지는 시험용 대표 세션. 이 PC에서는 쓰지 않음 |
| 그록봇 | 원본 문서의 외부 에이전트 보기 이름 |
| (verify) | 원본이 실제 기계에서 확인하지 못한 줄 |

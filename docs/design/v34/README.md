# 욱채 렌더러 v3.4 · Design B

**판정: 대표에게 보여 줄 준비가 끝나지 않았다.** 바쁜 작업실의 착석 페인트 순서와 주요 동작은 개선됐지만, 300초 대기 장면에서 두 사람이 같은 통로에 겹친다. 긴급 정지 때 프로듀서가 자기 자리에서 멀리 멈추고, 1440px에서는 그 이름표가 화면 아래 요소에 가려진다. 가까운 줄 한 자리의 작업 움직임도 목표치에 못 미친다.

## 검증

- `npx tsc --noEmit -p tsconfig.web.json`: 통과.
- `npx vite build --config vite.web.config.ts --outDir docs/design/v34/build`: 통과. 빌드는 허용된 렌더러 폴더 안에 생성했다.
- 렌더러 Vitest: **83/84 통과**. 남은 실패는 `motion.v33.test.ts`의 300초 대기 시뮬레이션으로, 52.2초에 M-0016과 M-0022가 겹친다.
- 고정 시계 시뮬레이션은 보고 수신함 도착, 7초 업무 배정 방문, 축하를 재현한다. [변이 검사](mutation-check.json)는 의자 키 308, 가까운 책상 키 472, 37u 튐, y=240 통로, x=575 연결부, 자세 기반 이름표, 5초 보고를 포함해 **14/14**를 잡았다.
- AC-05 2개 통과, 브리지 계약 62개 메서드·6개 토픽 통과. 인증·설정 초안·브라우저·백엔드 뷰·문구·글꼴 검사는 각각 별도 브라우저 검사로 확인했다.
- 검증 가능한 캡처를 위해 작업실의 정지·주기·버스트·검수 장면을 실제 개발 서버에서 다시 열었다. 이 서버는 이 작업에서 시작한 것이 아니다.

## 남은 일

1. 통로에서 서로 마주 오는 사람의 양보와 대기 규칙을 넣고 300초 대기 검사를 통과시킨다.
2. 보고 왕복과 긴급 정지 순서를 다시 짜 프로듀서가 자기 자리 근처에 도착한 뒤 멈추게 한다. 1440px의 가려진 하단 이름표도 함께 확인한다.
3. 쉼터를 방문마다 바꾸고 회의 탁자를 실제 대화에 쓰며, 가까운 줄의 마지막 작업 자리 움직임을 100px/프레임 이상으로 높인다.

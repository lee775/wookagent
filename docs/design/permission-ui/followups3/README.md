# 1단계 화면 3차 후속 검증

2026-10-30. `src/shared/views.ts`의 `OwnerTodo`와 리드 결정 43을 읽고, 메인 에이전트에게 전해지지 않은 보류 목록을 홈에서 구분했습니다. 대표는 메인에게 명령하며 긴급 정지와 해제, 질문 답변, 보고서 승인과 수정 요청, 조회를 합니다. 데스크톱의 PC 사용자는 운영자 역할도 맡습니다. 기존 오크색과 세이지색 프레임을 유지했습니다.

## 항목별 결과

| 항목 | 결과 | 변경 파일 |
|---|---|---|
| 1. 긴급 정지 보류 | `reachesMain === false`이면 `보류된 작업 n건`과 지정된 회색 안내를 표시합니다. 바로가기는 `메인 에이전트 직접`을 대상으로 `긴급 정지로 보류된 작업에 대해: `를 넣습니다. true와 필드 생략은 기존 라벨과 재개 안내를 유지합니다. 재개 버튼은 추가하지 않았습니다. | [Home.tsx](../../../../src/renderer/src/screens/Home.tsx) |
| 2. 오류 할 일 | 기존 `??` 판정이 명시적인 false를 우선함을 확인했습니다. `검수자 없음 —` 메시지와 false를 함께 보내는 독립 테스트를 추가했습니다. 제품의 오류 판정 코드는 바꿀 필요가 없었습니다. | [permission-ui.test.ts](../../../../src/renderer/src/components/permission-ui.test.ts) |
| 3. 가짜 브리지 | false인 `todo-held-undelivered`를 추가했습니다. 필드가 없는 기존 `todo-held`도 남겨 이전 서버 안내를 확인할 수 있습니다. | [data.ts](../../../../src/renderer/src/api/fake/data.ts) |
| 4. 임시 폴더 정리 | 절대 경로가 작업 공간 안의 지정 폴더인지 확인한 삭제 명령을 제출했지만, 자동 승인 검토가 재귀 삭제를 정책상 차단했습니다. 삭제는 실행되지 않았으며 다른 방법으로 재시도하지 않았습니다. | 삭제 없음. `src/renderer/.followups2-test-temp`가 남아 있습니다. |

false는 목록이 상한에서 버려졌거나 목록 자체가 없는 경우를 모두 뜻합니다. 화면에서 두 원인을 추측하지 않습니다. 필드가 없는 이전 서버는 요청대로 기존 안내를 유지합니다. 추가 계약 변경은 필요하지 않았습니다.

회색 안내는 다음 문장을 그대로 사용합니다.

> 이 보류 목록은 메인 에이전트에게 전해지지 않았습니다. 필요한 조치는 명령창으로 메인 에이전트에게 알려 주세요.

Vitest와 Vite는 기존 설정의 ESM 로딩 안내를 출력했지만 검사는 통과했습니다. 설정 파일은 수정하지 않았습니다.

새 테스트를 먼저 실행했을 때 `S3-1.`은 기존 라벨 `보류 작업` 때문에 실패했고, `S3-2.`는 통과했습니다. 수정 후 두 테스트가 통과했습니다. `S3-1.`은 false, true, 필드 생략을 모두 확인하고, 실제 바로가기 핸들러로 대상과 초안을 확인합니다. 바로가기를 눌러도 작업 조작 API는 호출하지 않습니다. 기존 `S2-3.`의 false 우선순위 테스트도 그대로 유지했습니다.

| 항목 | 다시 넣은 버그 | 실패한 테스트와 단언 |
|---|---|---|
| 1 | false인 긴급 보류도 기존 재개 안내로 표시 | `S3-1.`: `보류된 작업 3건` 라벨 없음 |
| 1 | 긴급 보류 초안을 `이 보류 항목에 대해: `로 되돌림 | `S3-1.`: 실제 명령 초안 불일치 |
| 1 | 필드 생략도 전달 실패로 판정 | `S3-1.`: 이전 서버의 `보류 작업` 라벨 없음 |
| 2 | `??`를 `||`로 바꿔 `검수자 없음 —` 문구가 false를 덮음 | `S3-2.`: `보류된 작업` 라벨 없음 |

상세 실패 증거는 [mutation-results.json](mutation-results.json)에 있습니다. 변이 도구는 [mutate-followups3.mjs](../../../../src/renderer/tools/mutate-followups3.mjs)입니다. 개발 서버를 끈 상태에서 실행하면 소스가 잠시 바뀌는 동안 화면이 갱신되는 일을 피할 수 있습니다.

## 변경 범위와 남은 사항

제품과 테스트 변경은 위의 세 파일이며, 재실행 도구 두 파일과 이 폴더의 README, PNG 두 장, JSON 두 개를 추가했습니다. 변경 경로는 `src/renderer/`와 `docs/design/permission-ui/` 안입니다. 서버, preload, 공유 계약, 인수·회귀 테스트, 패키지와 설정 파일은 수정하지 않았습니다.

`npx vite --config vite.web.config.ts --port 5196 --strictPort`로 별도 서버를 실행했습니다. 촬영 후 이 작업에서 시작한 서버 프로세스만 종료했고, 5196 연결 실패를 확인했습니다. 5199 서버에는 조작을 하지 않았습니다. 캡처용 Chrome도 직접 시작한 인스턴스만 닫았고 해당 프로필을 정리했습니다.

검사 임시 경로는 `src/renderer/.followups3-test-temp`로 지정해 인수 테스트의 임시 저장소도 작업 공간 안에 두었습니다. 직접 git 명령이나 패키지 설치는 실행하지 않았습니다. 지정된 인수 테스트는 내부에서 임시 저장소의 Git 동작을 검증합니다. 외부 업무일지는 기록하지 않았습니다.

미완료는 정책으로 차단된 `.followups2-test-temp` 삭제 한 건입니다. 화면 구현과 요청된 검증은 완료했습니다. 병행 중인 백엔드 round 6 수정 자체는 이 작업의 범위 밖입니다.

## 키별 이동과 판단

| 접두사 | 제목 | 관련 화면 | 메인 명령 바로가기 |
|---|---|---|---|
| `usage:<kind>` | 사용량 한도 | 설치 설정 | 없음 |
| `usage:<kind>:<family>` | 계열 이름 + 주간 한도 | 설치 설정 | 없음 |
| `mock-on` | 모의 실행이 켜져 있음 | 설치 설정 | 없음 |
| `execution-reset` | 실행 설정을 기본값으로 되돌림 | 실행 설정 조회 | 메인 직접, `실행 설정에 대해: ` |
| `review-stuck:` | 검수 멈춤 | 링크의 작업 | 작업의 프로젝트, `ID "제목"에 대해: ` |
| `handoff-stuck:` | 메인 에이전트 처리 지연 | 링크의 작업 | 작업의 프로젝트, `ID "제목"에 대해: ` |
| `pause-stuck:` | 메인 에이전트 처리 지연 | 링크의 팀원 | 팀원의 프로젝트, `ID 이름(역할)에 대해: ` |
| `crash:` | 자동 복구 실패 | 서버 링크. 링크가 없으면 프로젝트 | 프로젝트, 빈 초안 |
| `start-fail:` | 업무 시작 실패 | 서버 링크. 링크가 없으면 프로젝트 | 프로젝트, 빈 초안 |
| `spin:` | 헛돌기 | 서버 링크. 링크가 없으면 프로젝트 | 프로젝트, 빈 초안 |

- 알림 키가 undefined 또는 null이면 기존의 서버 제목과 링크, 링크 대상별 초안을 유지합니다. 모르는 키는 서버 제목과 링크를 보이며 별도 명령 바로가기를 만들지 않습니다.
- 종료 실패 계열의 프로젝트는 링크를 우선하고, 연결된 작업·팀원과 세션 키의 프로젝트 ID로 보완합니다. 프로젝트가 없는 메인 직접 세션이면 메인 직접을 대상으로 합니다. 건별 `:Q-…` 접미사는 종류 판정에 영향을 주지 않습니다.
- 인증과 모의 실행은 설치 설정에서 운영자가 처리하므로 메인 명령 바로가기를 붙이지 않았습니다. 실행 설정 값 변경은 메인에게 요청할 수 있습니다.
- 이전 서버의 오류 할 일은 메시지에 `검수자 없음 —`이 있는 경우만 처리 중으로 표시합니다. 명시적인 false가 오면 이 문구가 있어도 false를 따릅니다.
- 작업 상세는 자동 검사, 다시 판정, 일반 보류 순으로 안내를 고릅니다. 남긴 파일은 해당 보류가 가리키는 검사 실행만 봅니다. 다른 검사에서 남긴 파일은 영향을 주지 않습니다.

## 완료 범위

요청한 다섯 항목은 모두 완료했습니다. 1차 후속에서 남겼던 알림 키와 검수 알림의 작업 ID 문제도 해결했습니다. 이번 화면 작업에 필요한 추가 계약 변경은 없습니다.

변경은 `src/renderer/`와 `docs/design/permission-ui/` 안에 있습니다. 서버와 공유 계약, preload, 인수·회귀 테스트, 패키지와 설정 파일은 수정하지 않았습니다. 직접 git 명령, 설치, 커밋, 외부 업무일지 기록은 하지 않았습니다. 지정된 인수 테스트는 자체 임시 저장소를 사용합니다. 5196 개발 서버만 사용한 뒤 종료했고, 5199 서버는 그대로 두었습니다. 백엔드 round 5와 5단계로 남긴 서버 항목은 이 작업의 범위 밖입니다.

정리 예외: 자동 승인 검토가 `src/renderer/.followups2-test-temp`의 재귀 삭제를 정책상 차단했습니다. 삭제는 실행되지 않았으며 이 폴더의 `node-compile-cache`만 남았습니다. 기능 구현이나 검사 결과에는 영향이 없습니다. 종료 확인 요청에서 5196 서버에 연결되지 않는 것도 확인했습니다.

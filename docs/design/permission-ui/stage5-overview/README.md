## 결정과 이유

- 오류, 병합과 복구의 `reachesMain === true`는 `메인 에이전트가 처리 중`입니다. false는 명령창으로 알리는 출구를 표시합니다. 필드가 없을 때만 기존 규칙을 사용합니다. 홈의 `검수자 없음 —` 문구 판정과 작업 상세의 `no_reviewer`, `rejudge`, 자동 검사 실행 참조 판정을 이 경우에만 유지했습니다.
- 작업에 여러 보류 사유가 있으면 사유마다 안내합니다. 한 사유의 true가 다른 사유의 false를 가리지 않습니다. 검사에서 남긴 파일과 기록된 결과에 관한 기존 설명은 false와 필드 없음에 유지하고, 실제 검사 실행 기록도 계속 표시합니다.
- 현재 안내를 먼저 표시하고, 원문 메모는 닫힌 `보류 당시 기록` 안에 보존합니다. 홈의 메인 처리 항목은 작업 ID와 제목을 기록 밖에 표시합니다. 과거의 `명령창으로 메인 에이전트에게 알려 주세요`가 현재 처리 중 안내와 동시에 출구처럼 보이지 않으며, 기록은 펼쳐 읽을 수 있습니다. 메모를 삭제하거나 다시 쓰지 않습니다.
- 홈은 `대표 할 일`, `메인 에이전트가 처리 중`, `확인이 필요한 항목`으로 나눴습니다. 대표 할 일은 질문, 읽지 않은 보고서와 정지 상태만 셉니다. 정지와 관련된 기록이 여러 개여도 정지 상태는 한 건입니다. 오류, 복구와 인증 경고는 이 숫자에 포함하지 않습니다. 명시적인 true 항목은 메인 그룹에만 놓습니다. 필드 없는 검수자 없음도 기존 안내에 따라 메인 그룹에 놓습니다.
- 같은 작업에 두 오류 사유가 있으면 예전 서버가 같은 todo ID를 두 번 보낼 수 있습니다. ID별 등장 순번을 한 번 부여한 뒤 그룹을 나눠 각 행의 키로 사용합니다. 두 행을 합치거나 버리지 않습니다. 서버가 사유별 ID를 주지 않는 중복 항목은 원래 배열 순서로 구분합니다.
- 역할은 `roles.list`를 유지하고 `snapshot.version`이 바뀔 때 다시 읽습니다. 이전 요청이 늦게 도착해 최신 결과를 덮지 않도록 effect 해제 시 결과를 무시합니다. `createdBy`가 있으면 `ROLE_CREATOR_LABEL`로 태그를 표시하고, 없으면 아무 태그도 붙이지 않습니다. 생성자는 기록이며 편집 권한이 아닙니다. 역할 수정 UI와 쓰기 호출은 추가하지 않았습니다.
- 설정의 보류와 복구 설명은 각각 작업 상세와 홈에서 전달 상태를 확인하도록 바꿨습니다. 필드가 없거나 알림이 중단된 경우에도 참인 안내입니다.
- 에셋은 공유 `TASK_TYPE_LABEL.asset`을 그대로 사용합니다. 작업 상세와 역할 담당 유형에서 `에셋`으로 보이며, 출력 방식에 따라 보관된 음원과 이미지 파일을 표시합니다. 사운드 예제는 메인이 만든 역할이며 담당 유형은 `['asset', 'research']`입니다. 에셋의 산출물형 출력은 코드 변경 diff를 만들지 않습니다.
- 스튜디오는 기존 프로젝트 필터를 유지하고, 활동의 `memberId === 'M-MAIN'`이면 이름을 `메인 에이전트`로 표시합니다. 프로젝트 팀원 목록이나 서버의 예전 이름에 의존하지 않습니다.
- **S2-fake, S2-3, S2-4와 검사 힌트의 기대값 변경은 S5-24의 결정 반영입니다. 검사를 약화한 것이 아닙니다.** `true ⇔ no_reviewer`는 더 이상 계약이 아닙니다. fake의 todo와 사유별 필드가 맞는지 확인하고, 오류와 병합 true, 복구 true, false, 필드 없음의 정확한 화면 안내를 검사합니다. 잘못된 힌트를 다시 넣으면 실제로 실패합니다.
- 전체 renderer 검사를 실행하면서 기존 `seat.ts`의 참고 예제 금지어 검사 두 건도 재현했습니다. 테스트는 유지하고, 일지의 표현을 `탐색 항목`과 `보고서를 제출했습니다`로 고쳤습니다. 이 예제를 참조하는 질문 링크 테스트도 새 이름으로 맞췄습니다.

`--configLoader runner --no-cache`는 설정 번들과 검사 캐시 임시 파일을 저장소에 남기지 않기 위한 옵션입니다. 인수 테스트 내부에서 사용하는 임시 저장소도 시스템 임시 폴더에 생성됩니다.

2026-11-03 10:13 한국 시간의 인수 검사에서는 21개가 모두 통과했습니다. 같은 명령을 10:21에 다시 실행하자 메인 턴 시작 활동에 `Cannot read properties of undefined (reading 'digestFor')`가 세 번 기록되고 대표 요청이 중단됐습니다. 호출 위치는 `src/main/orchestrator/turns.ts:984`의 `this.core.overview.digestFor(...)`입니다. AC-23의 메인 턴과 AC-21의 보고서 턴이 시간 초과로 실패했습니다. 실제 프로세스의 전체 흐름과 수정 요청 흐름도 지시 등록 전 준비 단계에서 시간 초과가 나서 관련 테스트 7개가 실행되지 않았습니다. 최신 결과는 성공으로 보고하지 않습니다. 오류는 동시에 변경 중인 backend의 메인 턴과 요약 연결에서 발생했으며, 화면은 이 경로를 호출하지 않습니다. 해당 코드와 테스트를 수정하지 않았습니다.

## 범위와 남은 일

요청한 화면 구현, fake 예제, renderer 테스트와 캡처는 모두 완료했습니다. 최종 인수 검사의 전체 통과 조건은 backend의 `digestFor` 연결 오류 때문에 달성하지 못했습니다. backend 수정과 재검증은 리드에게 남깁니다. 실제 backend와 CLI를 연결한 보류 전달 검증은 이번 범위에 포함하지 않았습니다. 화면은 지시대로 fake bridge로 검증했고 `tsconfig.node.json` 검사는 실행하지 않았습니다.

수정은 `src/renderer/`와 `docs/design/permission-ui/` 안에서만 했습니다. main, server, preload, shared, `tests/`, resources, 패키지와 설정 파일은 수정하지 않았습니다. 패키지 설치와 git 명령을 직접 실행하지 않았습니다. 외부 업무일지는 리드가 기록합니다.

직접 실행한 5196 서버와 전용 Chrome은 종료했고, 촬영용 시스템 임시 폴더와 브라우저 프로필은 제거했습니다. 5199와 다른 작업의 프로세스는 조작하지 않았습니다. 저장소에 새 테스트 임시 파일은 남기지 않았으며, 제거가 막혀 남은 경로도 없습니다.
